# Excel 文件处理网站——网页布局与交互设计

> 版本：V1.0  
> 日期：2026-09-15  
> 关联文档：`Excel文件处理网站-开发需求与技术设计.md`  
> 原型入口：`../prototype/index.html`

## 1. 设计目标

- **简洁**：一个页面只突出一个主要动作，减少重复标题、说明和装饰。
- **清晰**：结果组顺序就是匹配优先级；条件树层级和 AND/OR 关系必须一眼可辨。
- **可信**：始终展示源文件、处理范围、命中行数、未匹配行数和异常提示。
- **适合大表格**：以桌面端为主，保证宽表预览、固定表头和分页操作的可用性。
- **渐进呈现**：默认显示常用配置，高级规则、格式说明和异常明细按需展开。

## 2. 信息架构

左侧只保留三个一级入口：

1. **文件概览**：继续上传、切换或删除多个工作簿，查看当前文件的 Sheet 和列结构。
2. **筛选处理**：管理有序结果组、编辑条件树、预览和下载结果。
3. **跨表求和**：选择列匹配方式、确认数值规则、查看汇总与异常。

页面顶部固定显示当前文件和全局操作，避免用户在不同功能间切换后失去上下文。
左侧导航下方显示已上传工作簿列表；当前文件使用绿色选中态，切换后所有处理入口都指向该文件。
工作簿名称不使用单行省略号，允许自动换行完整显示；文件卡同时显示大小和 Sheet 数，列表超出视口后内部滚动。

## 3. 桌面布局

```text
┌──────────────┬──────────────────────────────────────────────────────────┐
│ 品牌与文件    │ 当前页面标题                         保存方案  开始筛选 │
│              ├──────────────────────────────────────────────────────────┤
│ 文件概览      │ 文件摘要：Sheet 数 / 数据行 / 列数 / 文件格式          │
│ 筛选处理      ├─────────────────┬────────────────────────────────────────┤
│ 跨表求和      │ 结果 Sheet 列表  │ 条件树编辑器                           │
│              │ 顺序即优先级     │ 结果名 / 源范围 / AND-OR 分组          │
│              │                 │                                        │
│              ├─────────────────┴────────────────────────────────────────┤
│ 帮助与隐私    │ 结果标签：美式 / XJ-前缀 / teacher / 未匹配            │
│              │ 在线分页表格                                             │
└──────────────┴──────────────────────────────────────────────────────────┘
```

### 3.1 左侧导航

- 宽度 216px，使用白色背景和细分隔线。
- 顶部是产品标识和当前文件卡片；文件卡片只显示文件名、大小和解析状态。
- 导航项使用图标、短标签和单一选中态，不显示二级树。
- 底部说明“处理记录由用户手动清理”，并提供单条删除和清空记录入口，不使用营销文案。

### 3.2 页面标题区

- 左侧显示页面标题和一句说明。
- 右侧只保留一个主按钮，例如“开始筛选”或“开始求和”；“保存方案”等次要动作使用描边按钮。
- 任务运行时主按钮切换为进度状态，避免重复提交。

### 3.3 文件摘要

- 使用一条紧凑信息带展示文件名、格式、Sheet 数、总行数和列数。
- 异常信息使用黄色提示条，不与成功状态混用。
- 文件摘要不做成大面积数据卡，避免占用表格空间。

## 4. 筛选处理页

### 4.1 结果组列表

- 位于工作区左侧，宽度 280px。
- 每个结果组显示：优先级序号、名称、处理范围、条件数量、最近命中行数和状态。
- 支持拖拽排序和上移/下移；列表顶部明确显示“从上到下首次命中”。
- 当前选中组使用浅绿色底和绿色左边线，不使用大面积高饱和填充。
- `未匹配` 固定在底部，使用灰色系统标签，不允许重命名、删除或移动。

### 4.2 条件树编辑器

- 顶部字段只有“结果 Sheet 名”和“处理范围”。处理范围默认“全部 Sheet”，下拉框自动列出源工作簿全部 Sheet。
- 根条件组默认 AND。每个条件组头部显示 AND/OR 分段开关、添加条件、添加子分组和删除。
- 子分组使用 16px 缩进、浅色背景和左侧竖线表达层级，不依赖括号字符堆叠。
- 条件行固定为“列 + 操作符 + 值 + 删除”。为空/非空时隐藏值输入框。
- “以前缀开头/以后缀结尾”的值输入框在聚焦时弹出候选菜单，候选按当前处理范围扫描，并显示出现次数。
- “无前缀/无后缀”改为标识符输入；默认提供 `-`、`_`、`@`、`/`、`.`，同时允许自定义 1～5 个字符。
- 表头下拉项显示覆盖率，例如“备注 · 3/4 Sheet”，帮助用户理解全部 Sheet 模式。
- 条件树底部生成一行只读自然语言摘要，便于复核复杂逻辑。

### 4.3 结果预览

- 位于页面下半区并横跨结果组列表和条件编辑器。
- 标签顺序与最终工作簿 Sheet 顺序一致，`未匹配` 永远在最后。
- 全部 Sheet 模式下第一列为“来源 Sheet”；单 Sheet 模式不添加该列。
- 表头固定，首列可固定；使用服务端分页，不一次渲染全部数据。
- 顶部显示“命中数 / 总数 / 异常数 / 最近执行时间”。
- 下载前若条件或排序已修改，结果区域显示“结果已过期”，主下载按钮不可用。
- 新结果先以临时状态显示，不自动进入处理记录；用户点击“保存处理记录”后才进入下方历史区。切换一级页面不会清空当前结果，历史记录由用户逐条删除或清空。
- “保存条件”会把当前结果组按结果 Sheet 名称加入“已保存的筛选条件”；点击保存方案会重新选中该结果组、滚动到编辑区并允许保存修改。

## 5. 跨表求和页

- 页面首先列出全部可用数据表：所有上传工作簿、已保存筛选结果、当前未保存的临时筛选结果。卡片显示类型、Sheet 数和总行数。
- 用户先选择数据表，再选择表头名称或固定列位置；列下拉框随数据源切换，临时筛选结果无需持久化即可立即求和。
- 顶部使用两张互斥选择卡：“按表头名称”和“按固定列位置”。
- 选择按表头名称时显示公共表头及覆盖率；选择固定位置时显示列字母与列序号。
- 在运行按钮旁用一行摘要展示解析规则：`$1,234.50 → 1234.50`、`12% → 12`、`(100) → 100`、`-100 → -100`、含文字不参与。
- 汇总表显示 Sheet、目标列、有效数值数、非数值数、空值数和求和结果。
- 点击某行的非数值数量，在右侧抽屉查看源行号、单元格位置、原始值和原因。
- 下载 `.xlsx` 固定包含 `汇总结果` 和 `异常明细` 两个 Sheet。

## 6. 文件概览页

- 未上传时居中显示一个克制的虚线上传区，并列出支持格式。
- 上传完成后显示 Sheet 列表、数据范围、表头状态和前 100 行预览。
- 对错误 dimension 元数据等可自动兼容的问题显示“已修正读取范围”，不要求用户理解 XML 细节。
- 对无法安全解析、加密或损坏文件，显示明确原因和可执行的处理建议。

## 7. 视觉规范

### 7.1 色彩

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 主色 | `#147D64` | 主按钮、选中态、运行成功 |
| 主色浅底 | `#EAF6F1` | 当前结果组、轻提示 |
| 页面背景 | `#F5F7F8` | 降低长时间查看疲劳 |
| 卡片背景 | `#FFFFFF` | 内容区 |
| 主文字 | `#17201D` | 标题、关键数值 |
| 次文字 | `#66736E` | 说明、元数据 |
| 边框 | `#E2E8E5` | 卡片、表格、输入框 |
| 警告 | `#B7791F` | 结果过期、部分 Sheet 缺列 |
| 错误 | `#C2413A` | 解析失败、非法条件 |

### 7.2 字体与尺寸

- 字体：`Inter, PingFang SC, Microsoft YaHei, sans-serif`，不依赖在线字体。
- 页面标题 24px/700；区块标题 15px/650；正文 14px；辅助文字 12px。
- 基础间距使用 4px 倍数，卡片内边距 20～24px，控件高度 36～40px。
- 圆角以 10～14px 为主；阴影只用于浮层和当前操作区域。

### 7.3 图标与文案

- 使用统一线性图标，不使用 Emoji 作为功能图标。
- 按钮使用动作词：“开始筛选”“生成下载文件”“添加条件”。
- 状态使用具体表达：“2 个 Sheet 缺少‘备注’列”，不使用模糊的“存在问题”。

## 8. 响应式与可访问性

- 设计基准宽度为 1440px，最低支持 1024px 桌面/平板横屏。
- 低于 1180px 时左侧导航收为图标栏，结果组列表移到条件编辑器上方。
- 低于 768px 时提供查看和简单运行能力；复杂条件树编辑提示用户使用桌面端。
- 键盘可访问所有按钮、下拉框和条件组；焦点样式清晰。
- 正文及主要控件满足至少 4.5:1 对比度；颜色不作为状态的唯一表达。
- 拖拽排序同时提供上移/下移按钮，保证键盘用户可操作。

## 9. 原型范围

静态原型用于评审视觉层级和主要交互，包含：

- 文件概览、筛选处理、跨表求和三个页面切换。
- 结果组选择、优先级展示、AND/OR 切换、结果标签切换。
- 全部 Sheet/单 Sheet 范围选择、首次命中提示和固定未匹配 Sheet。
- 求和匹配方式切换和结果表格。

原型不读取真实 Excel，不发起后端任务，也不代表最终前端组件或技术栈。
